1. 已解决 ✓（供了解过程，不必再审）

1.1 自拼容器 bug → 字虚/行叠压（已修复）

首版 T35 自拼 BRRES 容器：字典哨兵 8B 被吞、Textures 字典写成线性右链（非 NW4R Patricia）。实测症状 = 全部字体渲染的文字纵向压扁、行距塌陷、行叠行（旧截图已清理，以推导链 SVG 记录当时结论）。修复：字形像素移植进用户实验探针的成熟容器（Patricia 字典 refbits 0x50/51/52、section 0xE0 起点、160,064 步长），逐字节同构只换 8×160,000 IA4 像素块（tools/transplant_t35b.py）。修复后行距/压扁 已消失。

2.2 铁证：Dolphin 纹理 dump 只有页 0-3

会话期间 GPU 见过的字库纹理（Dump Textures）只有 4 张 400×400，与部署字库页 0-3 逐像素一致（diff=0）。页 4-7 从未被绑定到 GPU——文件里有 8 页（common.load_sections 解析确认 8 节），但对 dialogue 场景游戏只用了前 4 页。

2.3 关键矛盾：探针在标题场景能显示页 4-7

用户的实验探针把 title.seq 的菜单文本换成槽位码 0x400/0x500/0x600/0x700/0x7FB/0x7FF（页 4-7），同一 DOL 实测全部正常上屏且清晰。所以：

  • 注册表里页 4-7 的句柄在标题场景 可用（普通路径）
  • 对话场景（流式路径？）页 4-7 从不绑定
  • 两条路径的反汇编绑定调用结构相同（bl GXLoadTexObj@0x80105fa4，r4=0/GX_TEXMAP0）

2.4 反汇编已知信息

页→纹理查找（普通路径 0x8004A0C0，流式路径内联版 0x8004DE20）：扫注册表 0x80245728（256 项 × 8B：{u16 page@+2, u32 handle@+4}），page=code>>8，无页数钳制：

0x8004de20: clrlwi    r0, r3, 0x18      ; r0 = r3 & 0xFF
0x8004de24: ori       r3, r0, 0xff00    ; 选页命令 0xFF00|page
0x8004de2c: srawi     r0, r3, 8         ; page = r3 >> 8
0x8004de44: clrlwi    r4, r0, 0x14      ; page & 0xFFF
0x8004de48: addi      r6, r30, 0x5728   ; 注册表基址 0x80245728
0x8004de50: mtctr     r18               ; r18 = 0x20（流式按 64B 块×8 条展开扫，共 256 条）
0x8004de54: lhz       r0, 2(r6)         ; entry.page
0x8004de58: cmpw      r4, r0
0x8004de60: lwz       r0, 4(r6)         ; entry.handle（非 0 才有效）
...
0x8004dfc8: mulli     r0, r5, 0xd0      ; 字形条目 = [handle+8] + col*0xD0
0x8004e02c: bl        GXLoadTexObj      ; 绑定 GX_TEXMAP0

字形表构建器（0x80049DE4）：每页循环 256 字形 × 0xD0 字节，按 16×16 网格写 UV（lha r0, 0xe(r30) 为页内字形数上界），无 4 页钳制。

未找到的：注册表 0x80245728 的写入方（谁把 {page,handle} 写进去）。已试：全文本搜 0x80245728 物化点（23 处，多为读取）；搜 sth@2+stw@4 写入对（0 命中——可能句柄是整体 8B/16B 写入或用其他布局）。23 处引用：0x80049f8c/fb8/ff4、0x8004a0a0/a0d8/a10c/a184/a1b8、0x8004a4e0/a56c/a5bc/a78c/a830/a890/a934/af08、0x8004bf4c/c414/d260/dc88/e228/ec84/ecb8。

2.5 假设（待裁决）

H1：注册表由「场景/资源组加载」填充，对话场景加载的资源组只注册了 4 页（比如按 arc 里实际纹理数注册，而某处又把新页丢弃）。→ 需要找到注册表写入方确认。
H2：对话路径上游在构造选页命令时钳制了页号（如 page & 3、cmplwi page,4）。已扫绑定站上游未见钳制，但未穷尽整函数。
H3：对话文本走了 2d/cmn 的另一字体对象（tf.brtex/ctf.brtex），其纹理银行固定 4 槽（ctx+0x220 四指针）——但 dump 纹理与部署字库页 0-3 diff=0，说明对话用的就是本字库，H3 减弱。
H4：注册表条目写入时机在页纹理加载时；页 4-7 加载了但句柄写 0/未写（加载顺序或上限 bug）。
